# Writing Style Guide

## Core Principles

- Be concise and straight to the point
- Don't overuse bullet points — prefer prose when it flows better
- Technical audience: assume reader understands the codebase
- Omit information easily inferred from context

## Linking

Use markdown links to reference code:

- Classes/functions: `[ClassName](https://github.com/org/repo/blob/main/path/to/file.ts#L42)`
- Files: `[config.ts](https://github.com/org/repo/blob/main/src/config.ts)`

## What to Avoid

- Redundant context ("As discussed...", "This issue tracks...")
- Verbose explanations of obvious behavior
- Excessive formatting (headers for single paragraphs, bullet lists for 2 items)
- Filler phrases ("In order to", "It should be noted that")
